# FPGA Python 维护与 r7 源码交付验证

本轮先确认依赖，再维护 Python，最后生成 r7 源码包。正式构建、仿真和包完整性工具使用 Python，因此没有先发布旧脚本再补重构。规范正文统一在 [CODING-STANDARDS](CODING-STANDARDS.md)，显式范围见 [development_sources.json](development_sources.json)。

## 实际范围

61 个已有 Python 文件：CSI 22 个、骨架 10 个、当前启动消费控制 12 个、HDMI 捕获／解码工具 8 个、协议解码离线测试 1 个，以及发布／构建工具 8 个。软件主工程的 Python、第三方模型、心率和历史几何／滤波、历史诊断快照及已关闭候选工具未纳入全树重构。

56 个文件只改变排版，最终语法树保持一致；首轮 61 个文件的全部字符串及注释 token 逐项保持。5 个发布工具进一步提取原厂依赖筛选、启动器生成、缺失头文件恢复、仿真命令组装、合成测试向量及打包文档等辅助函数。打包器另将来源切换至已验证的维护中 RTL，收录 28 个 C++ 文件及其依赖，补齐独立构建需要的原厂头文件。

内嵌 Tcl／Shell、正则、源码替换片段按数据保存。设备脚本未导入或执行，仅静态解析／编译；原有 MMIO、SDK、设备连接、停止条件及长 EDA 等待策略没有借重构更改。工具范围内的四空格配置不传播到软件主工程。

## 检查结果

- 全部 61 个文件通过静态语法编译；未把带顶层操作的脚本当作普通模块导入测试。
- 710 项原厂依赖的路径与顺序和基线一致。
- 构建准备生成物与基线一致；7 个原生阶段分别模拟成功与失败，14 种命令／退出码路径一致。
- 新包独立解压后通过 ARM64 正式程序构建、8 项原生测试、20 个 C++ 翻译单元的双架构编译、420 窗数值比较及 CSI／骨架 RTL 仿真。
- 687 项实际 FPGA 输入及阶段脚本与上一轮完整实现一致；路径重定位单独归一化，未新增频率、器件库或约束变化，因此复用原物理资格证据，没有重跑完整 EDA。

输入比较首次发现两处旧流程从工作区读取的路由 Tcl 钩子。按原生脚本实际引用找到原文件后，与包内副本逐项比较通过；新包已独立收录它们。首次比较记录保留，不将初次缺项覆盖为原本通过。

验证入口：[Python 检查](../Deliverables/evidence/source-r7-20261104/python-checks.json)、[解压包检查](../Deliverables/evidence/source-r7-20261104/package-checks.json)、[FPGA 输入对照](../Deliverables/evidence/source-r7-20261104/fpga-input-comparison.json)。完整基线、测试脚本与原生日志本机留存于 `.local/python-source-r7-20261104`，不随 Git 提供。

源代码压缩包内只包含实际构建、仿真和校验所需的 Python 工具；其余本轮维护的 FPGA 开发脚本留在仓库，没有将历史设备操作变成包内默认入口。设备操作为零，编译容器恢复为初始停止状态。r7 内容、下载与发布核验统一见 [源码交付说明](../Deliverables/SOURCE-20261104.md)。
