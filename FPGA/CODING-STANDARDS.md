# FPGA RTL、C++ 与 Python 开发规范

本规范适用于 FPGA 目录中维护中的自研 RTL、C++、Python、头文件和测试。当前自研硬件的构建映射见 [current_sources.json](current_sources.json)，工程入口见 [README](README.md)。设备安全、冻结范围和执行边界服从项目 [AGENTS](../AGENTS.md)。

厂商源码、生成 IP、历史诊断快照、基线和冻结功能不参加全树格式化。修改混合来源文件时只整理自研接入区域，保留厂商署名与原始来源。软件主工程的真实 Tab／四列约定继续由其本地配置管理；本目录采用四个空格，不向其它目录传播。

## 参考依据与适用方式

参考本机官方分发工程 `Docs/26嵌赛开发/fpai_demo_fpga/rtl/adder_op/adder.v`、`rtl/gp/gp_io.sv`，以及配套应用 `fpai_demo_app/examples/1_single_input+ai/PLin+SingleNet+HDMI/src/adder_demo.cpp`。来源背景见 [资料索引](../REFERENCES.md)。这些参考文件本机留存，不保证随 Git 克隆提供。

借鉴端口分组、命名连接、逻辑分段和输入／输出含义说明；本规范的四空格、中文设计说明和状态命名是本项目约定，并非厂商强制规则。不照搬参考示例中的器件假设、延时赋值或 SDK 生命周期处理方式。

## 通用书写要求

- 使用 UTF-8、四空格缩进、文件末尾换行；以 110 列为阅读参考宽度。长字符串、协议数据和必要表达式可超出，不为折行改变内容。
- 一行一条语句；控制块不压缩成单行。相关声明放在一起，逻辑阶段间留空行，避免大量装饰分隔线。
- 使用有含义的英文标识符。数学局部量可保留 `x/y/z`；状态和协议常量应表达用途，避免读者依赖数字猜测含义。
- 中文注释说明设计原因、单位、时钟域、数据格式、所有权、边界和失败行为；保留有价值的既有英文注释。避免逐行翻译赋值或加入对话、临时批准记录。
- 不因统一风格修改公开接口、历史结果、供应商文件或无关目录。格式化工具只接受经核对的文件列表。

本目录 [.editorconfig](.editorconfig) 管理编辑器缩进；[.clang-format](.clang-format) 管理 C++ 与受支持的 Verilog 排版。本轮使用现有 clang-format 23.1.1；更换版本先检查实际差异，不隐含安装许可。配置保留 include 顺序、字符串内容及现有注释，不执行全树格式化。

## RTL

### 接口、命名与结构

端口按时钟／复位、请求、响应、数据和状态分组。自研模块实例使用命名端口连接，保留实例名。内部采用 `snake_case`；新增状态使用 `ST_`，CSR 字节偏移使用 `CSR_`，故障码使用 `FAULT_`，已有明确命名可继续使用。

按接口、常量、存储、组合计算和时序控制组织代码。状态编码、参数默认值、CSR 地址及错误码属于兼容性边界。常量命名时明确原位宽及有符号性，不将无尺寸表达式机械替换成窄常量。

### 行为与硬件推断

- 保留流水级数、同步 RAM 等待拍、复位极性及同步／异步方式；不为简短而合并状态。
- 保留非阻塞赋值顺序及同拍旧值语义，尤其是多处更新同一寄存器的优先级。
- 保留 RAM 推断模板、读写端口、读延迟、CDC 级数与属性。约束、调试或测试引用的层级名和信号名先核对引用再处理。
- 不在可读性重构中新增状态机默认恢复、改变满空判定、重排握手、修改算术截断或增加时序例外。

重构前：

```verilog
csi_polar polar(clk,resetn,polar_start,re,im,pb,pd,pe,pm,pa);
```

重构后：

```verilog
csi_polar polar (
    .clk       (clk),
    .resetn    (resetn),
    .start     (polar_start),
    .re        (re),
    .im        (im),
    .busy      (polar_busy),
    .done      (polar_done),
    .error     (polar_error),
    .magnitude (polar_magnitude),
    .angle     (polar_angle)
);
```

状态分支由 `5:begin polar_start<=1;state<=6;end` 改为：

```verilog
// ST_START_POLAR=5、ST_WAIT_POLAR=6，保留原编码。
ST_START_POLAR: begin
    // 同一时序块前部默认撤销请求，此处只置位一拍。
    polar_start <= 1'b1;
    state       <= ST_WAIT_POLAR;
end
```

上述片段展示阅读方式；工具对齐细节可不同，不作为功能验收条件。

## C++

沿用 C++17 和现有工具链；需要匹配 Icraft SDK 变参宏的目标沿用现有 GNU++17 方言，不修改 SDK 头文件。类型名称采用项目既有风格；局部变量和新辅助函数使用有意义的 `snake_case`，新增文件内常量使用 `kName`。公开函数、结构布局、CLI 参数、报告字段和退出码保持兼容。

将过长流程按输入解码、计算、比较和输出拆分为文件内辅助函数，优先放在匿名命名空间。不要为一次局部重构引入通用框架；不包含其它功能 `.cpp`、不访问其它模块私有状态、不复制算法。遵守直接依赖，新增辅助函数声明和定义应使调用关系清楚。

压缩的 CORDIC 更新片段：

```cpp
const auto old_x=x; x+=y>>iteration; y-=old_x>>iteration;
```

重构后明确旧值语义（以下示例与原片段的运算顺序相同）：

```cpp
const auto previous_x = x;
x += y >> iteration;
y -= previous_x >> iteration;
```

数值实现保留运算顺序、转换、定点位宽、舍入规则、随机序列和 `-ffp-contract=off`；不能以代数等价替代实际浮点／定点输出比较。

设备代码保留 MMIO 次数与顺序、屏障、SDK 调用顺序、锁范围、超时和错误传播。不得将普通 RAII 析构当作硬件停止证明，也不得借整理代码修改原有在途资源保留策略。历史 ABI 探针应注明适用范围，不能因编译成功成为当前运行入口。

## Python

维护范围按 [development_sources.json](development_sources.json) 显式列出；当前构建／打包工具一并遵循本节。软件主工程、第三方模型、历史诊断快照与冻结功能不因本节扩展而全树格式化。

使用四空格缩进、110 列参考宽度和 `snake_case` 命名；展开分号串联及单行控制块，按解析参数、准备输入、生成命令、执行、检查结果分段。过长流程提取职责明确的辅助函数，常量表达用途，中文注释说明路径来源、作用域及执行边界。

保留命令行参数、输出字段、退出码、子进程命令顺序和等待策略。Tcl／Shell／JSON、正则与源码替换片段都是数据，不改变其字符串内容；路径重定位只作用于生成副本。生成器的排版改动先检查语法树和字符串等价，结构调整比较生成文件、命令序列与失败传播。

不得为了导入测试而执行模块顶层操作。带板端、BOOT 或 SDK 操作的脚本只做静态检查及隔离模拟；没有新的设备任务授权不运行历史入口。新增命令工具将执行入口放在 `if __name__ == '__main__'` 中，保留原有资源释放与长期任务等待边界。

## 重构验证与构建来源

软件主工程的阅读规范见 [软件编码规范](../software/pose180_pipeline/CODING-STANDARDS.md)。检查硬件输入时区分只改注释／空白和 HDL 标记／连线／约束变化：前者核对完整输入及语法标记后可复用原实现证据，后者须完成受影响的实现流程。两者均须保留源码对应记录，不把软件重编译写成新 BIT 或实板验收。

1. 保存修改前实际源码和适用基线；区分开发目录旧变体与正式硬件实际输入。
2. 排版先核对语法标记；命名、连线和结构调整再运行行为测试。C++ 数值比较保存完整输出，RTL 对比输出值和发生周期，不只比较最后 PASS 文案。
3. 覆盖复位、背压、错误、完成、换帧和安全停止等受影响路径。只运行离线测试；硬件探针的编译不自动触发执行。
4. 使用明确源码映射准备新的隔离构建，保留原生退出码、日志及必要检查点。重构后的源码不能继续冒用旧 BIT 的资格记录。
5. 受影响的设计完成相应综合与物理验证；原厂 IP 与未受影响检查点复用。BIT生成、完整实现、实板观察及长期验收分别记录。

新候选入口为 [prepare_refactored_fpga.py](../tools/release/prepare_refactored_fpga.py)：`prepare` 显式指定合格依赖源码包和全新输出目录，按映射覆盖自研输入；`run` 校验已暂存输入身份后调用原厂适配流程。它不访问开发板，不改发布包，不把候选标记为已部署。

格式、命名、换行和无关文档哈希不作为硬件硬失败条件；功能、资源安全、实际输入身份与原生结果必须有证据。阶段完成后更新成果说明，其它文档链接引用本规范，避免多处维护同一规则。
